## Goal (Annika's wish)

When a WPForms registration export is imported into MailPoet, the subscriber record should also carry
Organisation, Titel/Ansvarsområde, Avdelning/Enhet and FINGER-membership (ja/nej). She exports from
WPForms (Tools → Export, ticking exactly: Medlemskap i FINGER-nätverket, Förnamn, Efternamn, E-postadress,
Titel/Ansvarsområde, Organisation, Avdelning/Enhet), fixes the file in Excel, imports into MailPoet with
"update existing subscribers". The fields must be the same for every list.

## Facts that shape the plan (verified on prod)

| Topic | Finding |
|---|---|
| MailPoet | 5.38.1 + Premium (valid key). Custom fields are **global per subscriber**, not per list. Types: text, textarea, radio, checkbox, select, date. |
| Existing custom fields | id 1 "Country" (textarea), id 2 "Project" (text), both created 2025-12-18 — look like tests. |
| Lists / tags | Main list id 21 "Nyhetsbrev, Svenska FINGER-nätverket" (738). Test list id 22 "Annika & Elin test". Tags already used as batch labels (e.g. "Inspirationstillfälle 260818"). |
| Import wizard | **CSV only** (paste or upload). Column → field mapping per column. "Update existing" switch. Tags apply to the whole batch. |
| Auto-mapping | Email column detected by content. Other columns auto-map only when the header **exactly equals** a MailPoet field name (incl. custom fields). "First name"/"Last name" also match English synonyms only — "Förnamn"/"Efternamn" must be picked by hand. |
| Values | Custom-field cells are stored raw (only date type validated). Checkbox = `1` ticked, anything else unticked; segments filter on `= 1`. |
| Overwrite caveat | On an update import every **mapped** column is written, so an empty cell wipes the old value. Only include columns that carry data for that form. |
| WPForms export | Checkbox fields are always split into one column per choice (cell = choice label or empty); the "Separate dynamic choices" option does not change that. Radio fields export as one column with the chosen label. Form 15199's Medlemskap is a radio since 2026-09-15 → one column. |
| WPForms licence | Basic. The WPForms MailPoet addon needs Plus (not part of approach A). |
| Dev site | MailPoet 5.38.0 **inactive**, no Premium, WPForms 1.9.8.7. Activating MailPoet on a DB copy risks cron/sending side effects, so the rehearsal is planned on prod against the test list instead. |

## Step 2 — Annika's export routine

1. WPForms → Tools → Export → form → tick the seven fields above → CSV (xlsx is fine for editing, but the
   final file must be saved as **CSV UTF-8**).
2. Membership column (radio → one column with the full sentence). Helper column, then paste values:
   - Swedish Excel: `=OM(ÄRFEL(SÖK("inte";A2));1;0)`  ·  English Excel: `=IF(ISERROR(SEARCH("inte",A2)),1,0)`
   - (`Jag vill bli medlem` / `Jag är redan medlem` / `…osäker…` → 1, `Jag vill inte bli medlem just nu` → 0)
   - Old exports with four split columns: 1 if any of the first three columns is non-empty, else 0; delete the extras.
3. Optional: rename `Förnamn`/`Efternamn` headers to `First name`/`Last name` for auto-mapping (otherwise pick
   them by hand in the mapping step).

## Step 3 — import

MailPoet → Subscribers → Import → Upload a file → check the mapping row (email auto, three text fields
auto, membership auto, first/last name by hand) → choose list(s) → optional tag = seminar name →
"Update existing subscribers' information: Yes" → Import.

Rules: include only columns that have data for that form (see overwrite caveat). A `0` in the membership
column un-ticks an existing subscriber — decide whether that is wanted or whether "nej" rows should be
filtered out before import (see open decisions).

**How re-import works** (from `lib/Subscribers/ImportExport/Import/Import.php`): with "Update existing
subscribers' information = Yes", every *mapped* column is written for existing subscribers — text as-is,
membership `1` = ticked, `0` or blank = un-ticked. Columns set to "Ignore field" are left alone. There is no
per-cell "keep old value"; the file is the truth for the columns it maps. Practical rule for Annika: map only
columns that carry data for that form, and remember that a `0` un-ticks a person who was ticked earlier.
No child-theme PHP is involved in approach A.
